# 电子回单获取性能分析

针对银企直联「电子回单获取」（调度任务 GetBankReceipts）的性能问题做归因分析。
核心方法：全量扫描调度日志 → 提取事件链时间线 → SEND/RECV 逐任务配对 → 各环节分段耗时 → 空查询识别 → 三候选判定 → HTML 报告。

开始前先加载 @references/gotchas.md。日志布局与统计陷阱都在其中，违反会得出错误结论。

## 输入（缺失时先向用户要齐）

1. 日志根目录：包含 `logging-YYYY-MM-DD.N.log` 分卷（目录套同名文件，或平铺文件）。
2. 一次执行的起止时间与数据表现，例如：2026-09-03 05:54:49 ~ 08:27:46，374 条，成功。
3. 业务日志标记（可选）：默认 `GetBankReceipts 电子回单下载`；不同环境可能不同，可先 grep 确认。

## 步骤

1. 环境检查：`python --version` ≥ 3.10 即可（脚本仅用标准库）。缺 Python 时停止并告知用户，不猜测结果。
2. 全量事件扫描（只读）：
   `python scripts/scan_receipt.py --logdir <日志根目录> --tag "GetBankReceipts 电子回单下载" --out receipt_events.json`
   事件类型：SEND 发送报文 / RECV 接收报文 / DL_OK 下载成功 / UP_REQ 上传影像 / UP_RSP 上传影像返回 / DB_OK 入库成功 / RM_OK 删除成功 / EMPTY 文件路径和内容都为空 / NO_RSP 未返回当前明细的电子回单记录 / LOCK_FAIL 加锁失败。
3. 分段耗时归因与空查询识别：
   `python scripts/analyze_receipt.py --events receipt_events.json --start "2026-09-03 05:54:49" --end "2026-09-03 08:27:46"`
4. 三候选判定（每一项都必须给出证据后才能下结论）：

   | 候选 | 判定为是的证据 |
   |---|---|
   | 单笔回单入库/影像上传慢 | 下载/上传/入库各环节合计占墙钟比例显著（基准健康值：下载中位 ~0.2s、上传影像 ~0.4s、入库 ~10ms） |
   | 慢SQL | 日志出现慢查询记录，或结合执行计划另行分析 |
   | 发送/返回报文慢 | SEND→RECV 的 RTT 合计占墙钟 > 80%（同时排除前两者） |

5. 空查询识别（本任务最常见的根因）：
   - 任务级空查询：RECV 后到下一 SEND 前无任何 DL_OK → 该任务返回 0 张回单。
   - 比较空任务与有回单任务的 RTT 分布：空任务中位/最大显著更高（如 8.4s/180s vs 0.4~11s）→ 银行侧长尾。
   - 统计 EMPTY（返回文件路径和内容都为空）与 NO_RSP（未返回当前明细记录）条数：银行返回了大量 Bill 却没有回单文件，这本身可能是对账差异的源头，要在报告里单列。
6. 并行度核查：事件线程名分布（只有 TaskThread-0 即单线程）；日志 `配置的线程数` 值。
7. 对账：DL_OK（下载成功）笔数 vs 用户给的条数表现；RTT 合计 + 本地环节 + 间隙 ≈ 墙钟（偏差 > 10% 先查漏）。
8. 生成 HTML 分析报告，固定章节：一句话结论 → 关键数据表（墙钟/任务数/RTT 占比/空查询占比/有效回单数）→ 三候选判定表 → 空查询长尾证据（最慢 TOP10、同账户跨日期对比）→ 根因链 → 分级优化建议 → 数据质量说明。
9. 优化建议分级基线：
   - P0：调度配置表中 GetBankReceipts（对应 bankno）行的并发线程数调 4~8（任务级锁已有保障，不改代码）；对当日已确认无回单的（账户,日期）做水位/已查标记，不再重查空任务。
   - P1：拿最慢样本（如空查询 30~180s）与银行侧核查反常长尾；确认空回单的生成/保留策略。
   - P2：大报文日志刷屏治理。

## 质量自查

- 每个数字都有日志证据来源（事件计数、配对数、各环节分位数）。
- RTT 合计 + 本地环节 + 间隙 ≈ 墙钟（偏差 < 10%），对不上先查漏再下结论。
- 三候选每个都明确"排除/确认"，不给无证据归因。
- 报告区分"已实测数字"与"推断"。

## 停止条件

- 日志目录不存在或没有分卷 → 停止，请用户确认路径与解压方式。
- 扫描后 SEND/RECV 事件数为 0 → tag 不匹配，先 grep 实际业务标记再重扫，不得空跑出报告。
- 对账偏差 > 10% 且找不到原因 → 报告标注"未对齐"，把已知与未知分开陈述。
